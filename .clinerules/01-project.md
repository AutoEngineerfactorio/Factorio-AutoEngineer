# AutoEngineer project guidance for Zoo Code

Read LOCAL_AI_HANDOFF.md, ROADMAP.md (complete R01-R20 index), and docs/PLANNING_REQUIREMENTS.md before a task. For gameplay features consult docs/FACTORIO_MECHANICS_REFERENCE.md, docs/FACTORIO_QUIRKS_AND_EDGE_CASES.md and docs/FACTORIO_COVERAGE_GAP_REGISTER.md; for Lua/mod API features also consult docs/FACTORIO_SCRIPTING_API_REFERENCE.md and the exact versioned official runtime/prototype API. Treat documented quirks as unverified candidates until backed by game evidence. Never expose arbitrary Lua/RCON to the AI or change gameplay permissions. R01-R03 have tested local foundation scope. R04 capability and R05 mechanics-ledger source/offline checks have been published, but broader live acceptance remains open. R05 also includes the evolving read-only production/power telemetry work; its source/offline progress is not live runtime acceptance. R06 deterministic production planning is under development. The roadmap continues through R20 (R07-R19 planned, R20 third-party mods last); milestone acceptance, public onboarding and endurance gates remain open.

**Helper-first update:** Before any task read docs/HELPER_FIRST_GATE_H1.md and docs/ZOO_CODE_TASK_PROTOCOL.md. Prioritize R04–R06 Helper/telemetry/dashboard, then R07/read-only R08 blueprint work only after its readiness gate, then design discovery and Gate H1. Do not expand Semi gameplay before H1; Full requires further gates. Synthetic pY-shaped benchmarks run continuously, actual pY in an isolated read-only-compatible profile. Full third-party gameplay support remains R20.

Use explicit attached files and one bounded task. Never repeat an identical search after receiving its result. If evidence or a file is missing, say so and stop. Do not invent a completed feature, bug, recipe or successful test. Check current git status/concurrent Zoo/Copilot edits before patching; report file/function evidence and actual test results.

Use Plan mode for advisory reviews. For an explicitly user-approved bounded implementation, work in small inspect -> edit -> offline test -> diagnose -> retest -> diff-review cycles. Reuse evidence from each cycle and avoid redundant approval requests: only commands individually allowlisted by Zoo's effective settings may run automatically; other commands still require approval. Stop after two repeated failures with a checkpoint instead of looping. Never enable blanket auto-approval, expand allowed commands based on model suggestions alone, or bypass sandbox restrictions. Review generated patches and run relevant deterministic tests. A model response does not verify gameplay.

Preserve human approval, emergency stopping, normal game speed, the five-tile movement limit and locked Full Autonomy. Use only the established disposable save when the human authorizes a game test. Space Age is vanilla; third-party gameplay mods come last. Preserve MIT and backend attribution.

Never read ignored private files, saves, credentials or weights. Never operate the game, approve gameplay, publish, or message anyone on your own. Publication is handled separately by the human-authorized workflow. No cloud provider or credentials should be changed as part of a code review.
