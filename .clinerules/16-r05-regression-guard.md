# R05 telemetry regression and Git safety guard — October 20, 2026

This rule supplements the existing Windows, testing, approval and tool-loop rules. It addresses an observed Zoo task regression. It does **not** authorize game operations, deletion, checkout, restoration, or auto-approval.

- Known-good state verified by an independent reviewer on October 20: `python -m pytest -q tests` returned **430 passed, 134 subtests passed**; `python -m ruff check agent tests` returned **All checks passed**. The live saved 2.1.22 telemetry sample validated with 3 item series, 0 fluid series and 1 electric network. These are **offline/replay** checks, not complete 1A live acceptance.
- Do **not** execute `git checkout HEAD -- <path>`, `git restore <path>`, `git reset --hard`, `git clean`, `move`/`mv` over existing source, or replace an entire nontrivial Python source file to repair one failing test. Those commands can erase uncommitted, previously passing telemetry implementation. Seek explicit individual user authorization for any destructive restore. A checkpoint is not permission to throw away working code.
- Before changing `agent/production_telemetry.py`, read `git diff -- agent/production_telemetry.py` and the specific failed assertion. Preserve current full-catalog support (`candidate_cap=10000`, selected 16 item/8 fluid histories), normalization of empty Lua array/object representations, and `convert_flow_rate`, `format_power`, `format_energy`, `power_rate_display`. Do not revert to the older hardcoded 128-item/4-series validator to satisfy tests.
- For Windows commands use `python -m pytest -q tests/test_production_telemetry.py` and `python -m ruff check agent/production_telemetry.py agent/telemetry_view.py tests/test_production_telemetry.py`. Do **not** pipe tests into `head`/`tail`, use Bash `mv`, or multiline Python one-liners malformed by shell quoting. Use the existing PowerShell-native practices from rules 08 and 11.
- Apply one surgical, evidence-supported change, run the focused tests/linter, inspect the diff. If two attempts fail or test coverage regresses, **STOP** with a concise diagnostic and ask for review rather than rewriting or repeating the action. Never claim 1A complete based on green unit tests alone.
- The user's R05 telemetry changes and unrelated uncommitted files belong to in-progress work. Preserve them. Keep Exa MCP research read-only and individual approval intact.
